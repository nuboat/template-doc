\textbf{การจัดการ Return URL (Redirect):} ตั้งแต่ ระยะที่ 1 ตอนที่ Service ต้นทางเตะผู้ใช้มาที่ SSO ระบบ SSO จะต้องจำค่า \texttt{redirect\_uri} หรือ Return URL เอาไว้เสมอ ไม่ว่าผู้ใช้จะเลือก Login ด้วยวิธีใด เมื่อผ่าน ระยะที่ 4 ระบบจะนำ URL นี้มาใช้เพื่อส่งผู้ใช้กลับไปอย่างถูกต้อง

\bigskip

\textbf{ความแตกต่างของระบบหลังฉาก (Backstage):}

\begin{itemize}
    \item \textbf{สาย LDAP (3A):} ระบบ SSO ของคุณจะทำตัวเป็นคนไปเคาะประตูถาม LDAP Server โดยตรง (Bind request) รหัสผ่านจะวิ่งผ่าน Server ของ SSO
    \item \textbf{สาย OAuth / IDM (3B):} รหัสผ่านจะ \textbf{ไม่ผ่าน} Server ของ SSO ผู้ใช้พิมพ์รหัสลงใน Popup ของ IDM โดยตรง SSO จะรอรับแค่ "ตั๋วยืนยัน" (Authorization Code) จาก IDM เพื่อมาประมวลผลต่อเท่านั้น ถือเป็นวิธีที่ปลอดภัยและเป็นมาตรฐานสากลครับ
\end{itemize}

\bigskip

\textbf{การจัดการ Popup (Frontstage 3B):} ในทางเทคนิค เมื่อผู้ใช้ Login ใน Popup เสร็จแล้ว หน้า Popup จะถูก Redirect กลับมาที่ Callback URL ของ SSO (หน้าต่างลูก) จากนั้นหน้าต่างลูกจะต้องส่งสัญญาณ (เช่น ผ่าน \texttt{window.postMessage}) บอกหน้าต่างหลัก (SSO หลัก) ว่าสำเร็จแล้ว เพื่อให้หน้าต่างหลักจัดการ Redirect กลับไปยัง Service ต้นทาง และทำการปิดหน้าต่าง Popup ทิ้งไปครับ
